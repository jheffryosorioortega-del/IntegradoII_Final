# 15.7 Pruebas de disponibilidad

**Objetivo:** comprobar que el sistema responde de forma continua y se recupera solo tras una caída.
**Entorno:** nube (https://serviciosgeneralespo.duckdns.org/) y local con Docker.

## Pruebas
| N.º | Prueba | Cómo se mide | Criterio de aprobado | Resultado |
|---|---|---|---|---|
| D1 | Monitoreo continuo del sitio | Petición a `/` cada 30 s durante 30 min | Disponibilidad ≥ 99 % | Pendiente |
| D2 | Estado de cada servicio | Endpoint de salud de ms-usuarios, ms-clientes, ms-solicitudes y gateway | Todos responden UP | Pendiente |
| D3 | Caída de un microservicio | Detener ms-clientes, enviar solicitud, reiniciar | Mensaje de error entendible y recuperación al reiniciar | Pendiente |
| D4 | Reinicio de la base de datos | Reiniciar PostgreSQL | Los servicios reconectan sin reiniciarse | Pendiente |
| D5 | Recuperación tras reinicio del servidor | Reiniciar contenedores | Sitio disponible en < 2 min | Pendiente |
| D6 | Disponibilidad bajo carga | Prueba k6 de 100 usuarios y revisar errores | 0 % de errores (ya medido: ver documento k6) | Parcial |
